# 3D particle bursts

`org.javity.particles` provides a bounded first particle effect: deterministic CPU-simulated world-space bursts drawn as camera-facing billboards with additive blending. It does not provide transparent sorting, soft particles, lighting, volumetric effects, or a general emitter editor.

## CPU pool and ownership

Register one `ParticleBurstPool3D` with a `Game` before `Game.start()`. Its default capacities are 1024 particles and 32 active burst leases; constructors can choose smaller fixed capacities. `burst(spec)` validates the immutable description before acquiring resources. It returns a generation-checked handle, or `null` if the whole burst cannot fit in the fixed particle or lease capacity. It never partially spawns, evicts another burst, or creates a `GameObject` per particle.

A description copies origin, component-wise minimum/maximum initial velocity, constant acceleration, color, size, lifetime, count and seed. Distances are world units, velocity is world units per second, acceleration is world units per second squared, and lifetime is seconds. The seeded generator chooses each velocity component independently and deterministically. Each update consumes at most the scene's one delta for that step and advances a cumulative double age; render positions are evaluated analytically from copied origin, sampled initial velocity and acceleration, so float output rounding never feeds back into simulation. There is no emission-rate catch-up loop. Particles expire at the configured lifetime. Before the description can be used by a pool, it validates a conservative whole-life envelope using double intermediates: component-wise maximum speed remains within `Float.MAX_VALUE`, and `abs(origin) + maxAbsVelocity * lifetime + 0.5 * abs(acceleration) * lifetime² + size` stays at or below `Float.MAX_VALUE / 4`. This includes the billboard's world-space extent and leaves headroom for float rounding. Unsupported descriptions throw before a lease or particle capacity can be acquired; large finite descriptions within the envelope remain supported. `pause`, `resume` and `cancel` affect only the matching lease generation. Reusing a lease slot cannot make an old handle affect its successor.

The pool is CPU-only. It owns fixed arrays and no graphics resources. Its clock can be `Clock.WORLD` (default) or `Clock.UI`; WORLD freezes with game pause/time scale and UI follows unscaled scene time. `copyRenderData` packs active particle position, size and color into caller-owned storage for a renderer.

`ParticleBurstFeedback3D.burst(pool, spec)` creates a `Feedback.resource` lease per playback. Cancellation/cleanup closes only that burst handle; the pool and renderer are shared services with separate lifetimes.

## GPU renderer

`ParticleBurstRenderer3D` requires an active GL30 context and must be constructed, drawn and closed on the same thread. It throws `UnsupportedOperationException` before allocating GPU resources if the active backend does not expose GL30. It owns one reusable indexed quad mesh, its vertex/index buffers and private VAO, plus one compiled shader program; all GPU resources are released by `close()`. It borrows the pool, the caller's sprite/atlas `Texture`, and the explicitly supplied presented libGDX `Camera`. Closing it never disposes the texture or pool. The sprite texture's alpha supplies the sprite edge; color is multiplied by each particle color.

Call `draw(pool, camera, texture, x, y, width, height)` after opaque world geometry and before the depth-isolated viewmodel and HUD. The currently bound framebuffer and its depth buffer are used. The adapter enables depth testing, disables depth writes, and uses additive `SRC_ALPHA, ONE` blending. It restores viewport, depth test/function/write mask, blend enable/equation/factors, active texture and binding, buffer bindings, current shader program, and the caller VAO, including when drawing fails. Restoring the caller VAO also restores its attribute descriptors and element-buffer binding. The adapter does not support GL20, because the libGDX backend cannot portably query vertex-pointer descriptors needed for exact state restoration. It does not capture a world render target or manage the host pass order.

The native fixture and measured evidence are in [artifacts](artifacts/particles3d/verification.json) and [the GL20 capability probe](artifacts/particles3d/gl20-unsupported.json). The GL30 pass checks real framebuffer pixels against an opaque model, depth values before/after the particle pass, cancellation independence, viewport resize, caller VAO and indexed mesh reuse, borrowed texture survival, and live-before/deleted-after state for owned GL objects. The separate GL20 API-emulation child process proves construction is rejected before GL state changes (`Gdx.gl30` is unavailable; Mesa reports a 4.5 Compatibility Profile context). Run both with `:javity-desktop:particleSmoke`.
