# JavityEngine render memory/allocation audit

Read-only audit at `48814ae` (Java 25, libGDX 1.14.2). No build or runtime measurement was run; allocation statements below are source-derived, not profiler results. Existing docs record desktop GL20/GL30 correctness gates and explicitly say historical instancing benchmarks are not fresh measurements (`docs/runtime-batch-verification.md`).

## Findings

**Highest-confidence repeated allocation source: scene-light snapshot.** Every `renderWorld` selects a new scene snapshot when `RenderEnvironment3D` is installed (`GdxRenderer.java:250-252`). `snapshot()` creates a new `Environment`, ambient/fog attributes, two capacity-sized float arrays plus copies, one `Color`, two `Vector3`s, and one libGDX light object per accepted scene light; it also walks `Game.getObjectsWith(Light3D.class)` (`RenderEnvironment3D.java:62-80, 81-145`). Default caps are small (2/4/2), so this is bounded per view, but repeats per rendered view/frame. The existing API already says the environment is borrowed until the next snapshot; that allows reusing renderer-owned environment/attributes/light instances while retaining copied values and atomic validation. Preserve object-ID/component order, overflow counts, and “failed candidate leaves prior snapshot intact.”

**Scene traversal itself allocates snapshots.** `Game.getObjectsWith(...)` builds a temporary list of component-index sets and returns a stream-produced, sorted `toList()` on every call (`javity-core/src/main/java/org/javity/core/Game.java:54-75`). World render calls it for camera selection, model/transform selection, and lights; 2D does camera and renderable queries (`GdxRenderer.java:215, 266, 521, 541`; `RenderEnvironment3D.java:81`). `render2D` additionally creates/sorts a new `ArrayList` each frame (`GdxRenderer.java:540-543`). This is shared core API behavior, not solely renderer code. A safe route is an iteration API over a stable/reusable scene index or caller-owned destination buffer, with deterministic ID order and mutation semantics specified; changing `getObjectsWith`’s return/ownership contract is an API change.

**Instancing paths allocate heavily in steady state and repeatedly rebuild temporary descriptions.** `StaticInstanceBatch.render` creates an owner `IdentityHashMap`, uniqueness `HashSet`, fallback array, visible-group `LinkedHashMap`, per-candidate `InstanceGroupKey` with nested lists/attribute snapshots and a per-key attribute `HashSet`, plus GL `State`, `RenderContext`, and texture binder (`StaticInstanceBatch.java:55-145`). `InstanceSlots.put` replaces a `Matrix4` for changed transforms; `pack` allocates per-chunk arrays, chunk records, copies, list, and immutable list each prepare (`InstanceSlots.java:36-47, 92-110`). `SkinnedInstanceBatch.render` creates uniqueness/used sets, fallback array, visible map/lists, a `Part`/`Key`/`Item` per candidate, and context/state; `BonePalette.put` copies each bone matrix set to a fresh float array and wraps it in `MatrixContent` on each candidate (`SkinnedInstanceBatch.java:62-160`; `BonePalette.java:107-138`). Each skinned chunk also gets a fresh packed float array (`SkinnedInstanceBatch.java:321-338`); `SkinnedBounds.world` allocates a result box and a transformed box per valid bone (`SkinnedBounds.java:62-72`). Both static and skinned `Group.prepare` copy a new `Material` per active group every frame (`StaticInstanceBatch.java:274-276`; `SkinnedInstanceBatch.java:321-324`). The instanced mesh allocates an attribute-location `int[]` per draw (`InstanceGpuTransport.java:~110`). These are clear allocation sites, but their actual frame cost depends on candidate/group/bone/draw count and must be measured before ranking against scene snapshot/traversal.

**Other steady-state sites:** avatar override builds a new `HashSet` for render keys per opted-in renderer per view (`GdxRenderer.java:285-288`); normal instanced renderer refresh creates a new identity set per renderer (`GdxRenderer.java:376-394`). `TextRenderer2D` copies its font color for each draw (`GdxRenderer.java:648-656`). `InstanceSlots.visible` builds a bounding box per call (`InstanceSlots.java:86-90`), though the present static batch packs with `id -> true` and does not use this method on the shown path.

**Caches are mostly pruned by scene/view, rather than clearly unbounded across frames.** Static groups prune keys not visible this render, and unused copied geometry is disposed (`StaticInstanceBatch.java:176-180, 212-235`); skinned groups, geometry and bounds similarly prune, and unused bone-count palettes are disposed (`SkinnedInstanceBatch.java:136-149, 226-251`). Renderer owner ID maps retain only current renderers/attached parts (`GdxRenderer.java:319-320, 376-394`). Thus no demonstrated cross-scene leak in the reviewed paths: instance batches are released when the world `Game` changes (`GdxRenderer.java:397-420`). However, peak group/geometry/palette storage has no explicit maximum tied to current visible group count or source mesh size; the per-group draw capacity 256 is **not** a total owner or memory cap (`InstanceSlots` class comment and constructors). `BonePalette` has a total 1024-row budget per skinned batch, but lazily stores a distinct palette per encountered bone count (`GdxRenderer.java:333`; `SkinnedInstanceBatch.java:119-125`). Consider an explicit retained geometry/group budget only if profiling shows extreme scene variety.

`ExactPoseCache` is intentionally frame-local and capacity-limited; overflow samples without retaining entries (`ExactPoseCache.java:8, 37-44, 68-75`). `SmoothShapeRenderer` documents a 32-program material cache limit in `AGENTS.md` (and releases it on dispose). These are examples to preserve, not evident unbounded caches.

## Architecture split and invariants

There is one `ModelBatch` and one `RecoverableDefaultShaderProvider`, but two `DefaultShader.Config` variants: stock legacy config (stock libGDX light capacities/behavior) and custom scene config with scene capacities and GLSL (`RecoverableDefaultShaderProvider.java:51-79`). `SceneLightingAttribute` is the discriminator; shader `canRender` prevents cross-mode reuse (`RecoverableDefaultShaderProvider.java:88-90, 179+`). Scene shader uniform upload is hand-written alongside libGDX legacy `DefaultShader.bindLights` (`RecoverableDefaultShaderProvider.java:179-257`). Separately, static and skinned instance paths own `InstanceShader` / `SkinnedInstanceShader`, with their own material/environment support checks; scene marker/fog currently rejects those candidates and sends originals through ordinary `ModelBatch` rendering (documented in `scene-lighting.md` and `runtime-batch-verification.md`). The rejection is an image-correctness boundary, not a safe performance “optimization” to remove.

Keep these isolation rules through consolidation:

- Scene environment and fog affect the world pass; `renderViewmodel` deliberately uses `GdxRenderer.environment` (legacy lighting) and excludes scene fog/sky (`GdxRenderer.java:582-599`; `docs/scene-lighting.md`).
- Sky is a separate pre-world pass; 2D world and SCREEN/UI use independent SpriteBatch/ShapeRenderer passes. No scene-lighting uniform should bleed into them (`GdxRenderer.java:517-580`; `SkyboxRenderer.java`).
- Scene component values are copied into the borrowed snapshot, never aliased as live light state. Cubemaps and user shaders remain borrowed/caller-owned (`docs/scene-lighting.md`, `docs/lighting-and-sky.md`).
- Shader recovery is location-cache repair on retained ModelBatch shader instances, pinned to libGDX 1.14.2. Refresh re-queries uniforms, vertex/instance aliases, bone attributes and light offsets; ordinary draws must not start querying GL (`RecoverableDefaultShaderProvider.java:278-331`; tests assert this). Sky independently re-queries raw locations and replaces its tiny mesh to rebuild VAO descriptors even when locations are unchanged (`SkyboxRenderer.java:90-110`; `docs/scene-lighting.md`). Keep this distinction: shader uniform cache recovery and mesh VAO descriptor recovery are separate responsibilities.

## Bounded next steps

1. **Capture a baseline before design changes.** Add/use a repeatable desktop scene-lighting/instancing workload with fixed visible model/light counts. Record allocation bytes/frame and allocation-class counts with JFR or async-profiler, plus CPU frame time separately; record GL draw/upload counts and existing `InstanceStats`. Profile scene on/off and static/skinned candidates. Label measurements with commit, JVM, backend and warmup. Keep the existing `environmentSmoke`, static/skinned GL20+GL30 smoke, and `RecoverableDefaultShaderProviderTest` as gates. Do not report source allocation counts as speedup.

2. **Unify configuration and shader contract without changing pass selection.** Introduce one immutable internal lighting/shader-capacity descriptor consumed by `RecoverableDefaultShaderProvider`, `InstanceGroupKey`, `InstanceShader`, and `SkinnedInstanceShader`; keep the public constructors and `renderer.environment` compatibility. First make ordinary, static-instance and skinned shaders consume equivalent scene ambient/directional/point/spot/fog inputs and preserve fallback for unsupported custom material/layouts. Only then allow scene-lit candidates into instance paths. This is the main architecture step; it risks shader parity, key collision, and fallback behavior. Gate with pixel-level scene smoke for ordinary + static + skinned, alpha-test depth holes, zero/default/advanced capacities, overflow ordering, viewmodel/HUD isolation, shader compile/link failures, and context restoration with moved uniform/attribute locations on GL20 and GL30.

3. **Reuse environment snapshot storage.** Update `RenderEnvironment3D.snapshot` in place using candidate values/scratch and reusable typed light/attribute objects, while committing only after validation. Keep the documented “valid until next call” lifetime, so no new public ownership burden. If retaining candidate-on-failure requires staging, use two reusable snapshots and swap only after successful validation. Gate equality of selected Environment attributes/lights/overflow against current behavior, failed invalid-transform snapshot preserving prior snapshot, multiple view calls, and environmentSmoke capture parity. Measure allocations/frame afterward.

4. **Reuse render scratch, then move allocations behind stable APIs.** Reuse renderer-owned 2D drawable buffers and scratch sets/lists; change instance batch temporary collections/packed transform buffers and matrix slots to capacity-managed reusable storage. Avoid building `InstanceGroupKey` per candidate by computing an immutable material/mesh/environment signature only when source state changes, or intern against existing groups. Preserve exact snapshot equality for attribute keys, stable owner IDs, fallback renderable identity, prune-on-absence, and geometry invalidation. `Game.getObjectsWith` needs either a new non-allocating iteration/destination API or a documented reusable snapshot API; this is a public API consequence and should be a separate change. Gate existing lifecycle/grouping/owner-ID tests, static/skinned real GL smoke, geometry mutation invalidation, scene replacement, and deterministic render ordering.

5. **Set explicit retention budgets only if baseline shows peak memory growth.** Add diagnostics for retained groups, copied geometry bytes, chunks and palette bytes before introducing eviction. Eviction must dispose owned GPU copies only, never source models/meshes/textures/cubemaps; maintain owner slot lifecycle and reconstruct lazily. Current prune-on-current-view strategy already bounds residency to current visible keys but has no configured peak ceiling, so avoid arbitrary limits that cause shader churn or visual fallback.

Primary targets: `javity-core/src/main/java/org/javity/render/lighting/RenderEnvironment3D.java`, `render/GdxRenderer.java`, `render/RecoverableDefaultShaderProvider.java`, `render/InstanceGroupKey.java`, `render/StaticInstanceBatch.java`, `render/SkinnedInstanceBatch.java`, `render/InstanceSlots.java`, `render/InstanceShader.java`, `render/SkinnedInstanceShader.java`, `render/BonePalette.java`, and `core/Game.java`. Tests: `RecoverableDefaultShaderProviderTest`, `GdxRendererConstructionTest`, `InstanceGroupingTest`, `StaticInstanceLifecycleTest`, plus desktop environment/static/skinned smoke gates. Docs to update: `docs/scene-lighting.md`, `docs/lighting-and-sky.md`, `docs/runtime-batch-verification.md`.

Keep public behavior unchanged in initial internal consolidation. A non-allocating `Game` iteration API is the one likely public API addition; document callback mutation rules and deterministic order. Any snapshot object reuse must honor its existing next-call invalidation rule. Do not make borrowed assets/shaders renderer-owned.
