# OneJS coverage audit

Audited 2026-10-15 against the current source and checked-in tests. This is a finite capability inventory for Javity's native UI host; it is not a score or a claim of full OneJS, browser, Unity, or Tailwind compatibility. “Yes” means the named capability has a concrete implementation and source or test evidence. “Partial” means only the listed subset is present. “No” means no implementation was found in the audited modules.

The host runs GraalJS Community on an ordinary JDK 25, with a bundled React 19 mutation renderer. It commits a small declarative tree to `UiDocument`, which builds Scene2D actors and LWJGL Yoga nodes. TSX is built separately by esbuild; the Java build consumes checked-in bundles. The runtime has no browser DOM, Node APIs, arbitrary Java reflection, or script file/network access. See [the port guide](onejs-port.md), [the declarative UI contract](declarative-ui.md), and [the React host README](../web/javity-ui/README.md).

## Capability matrix

| Area | Status | Implemented and evidenced | Concrete gap |
| --- | --- | --- | --- |
| DOM | Partial | JSX host nodes are reconciled to keyed native `UiDocument` entries. Supported controls are `View`, `Text`, `Button`, `Progress`, `TextField`, `ScrollView`, `Toggle`, `Slider`, and `Image`; lowercase aliases include `div`, `span`, `label`, `button`, `progress`, `input`, `scroll`, and `img`. | This is not a browser DOM. There is no `document`, element/query API, CSSOM, layout/style inheritance model for arbitrary elements, browser default behavior, or general HTML tag support. The markup parser is a secure XML-compatible subset, not an HTML parser. |
| JavaScript | Partial | GraalJS runs embedded JavaScript. Host timers, intervals, animation frames, `queueMicrotask`, and `performance.now` advance through `ScriptUiRuntime.tick`. The bridge exports only registered named actions, primitive values, and signals. | There is no Node runtime, package resolver, browser API set, Java reflection, host IO, or network API. The callback ceiling does not limit synchronous JavaScript or Graal Promise jobs, so this is not a hostile-script sandbox. |
| TSX | Partial | App `.tsx` files are compiled by the package's esbuild scripts into checked-in bundles; application imports use a shim over the host's existing React instance. The documented workflow builds host, sample, and MM bundles separately. | TSX does not compile inside GraalJS. Authors must run the separate npm/esbuild workflow; there is no integrated watch-to-runtime bridge in the host, and the package has no TypeScript type-checking step. |
| React | Partial | Bundled React 19 and `react-reconciler` use a single mutation root. Source supports function components, keyed native nodes, fragments, text children, and React state/effect hooks; host-tree tests cover state updates, fragments, handlers, props, images, and text wrapping. | The host config explicitly disables persistence and hydration. It has no browser renderer, multiple roots, portals, server rendering, or React DevTools integration. Do not infer complete React DOM semantics or support for every React feature from the included examples. |
| Tailwind / CSS | Partial | `UtilityStyles` strictly recognizes an explicit vocabulary for flex direction/wrap, grow/shrink, alignment, spacing, dimensions, text sizes/colors, backgrounds, rounded corners, borders, opacity, and hover/active/focus/disabled visual states on selected controls. React inline styles map only width, height, padding, gap, color, and background color. | It does not parse CSS or implement the complete Tailwind catalog. Responsive/breakpoint, pseudo-element, arbitrary CSS, theme/config/plugin, and unsupported utility semantics are absent; unknown classes and props fail. |
| Yoga | Partial | Native LWJGL Yoga nodes drive Flex layout for the native tree. Tests cover stable keyed actors, nested layout, dimensions, spacing, scroll measurement, and style validation. | Only the implemented `UtilityStyles` vocabulary is exposed through markup/React. There is no general CSS-to-Yoga style object, browser layout engine, or Yoga-backed Android/web adapter in these modules. Rounded visuals do not clip children or alter hitboxes. |
| Input / events | Partial | Native controls handle pointer interaction through Scene2D listeners. `UiDocument` exposes click, text change, controlled Toggle/Slider change, focus/blur, key down/up callbacks, Tab/Shift+Tab navigation, Enter/Space activation, and Slider arrow keys. Tests cover the typed control and runtime callback contracts. | There is no general browser event model or React synthetic event object. The bridge passes primitive control values or `UiKeyEvent`; arbitrary pointer/mouse/touch/wheel/drag handlers and browser event propagation/capture are not exposed as host props. |
| Assets | Partial | `UiTheme.registerImage` maps a name to a borrowed `TextureRegion`. `Image`/`img` accepts that source name and `contain`, `cover`, or `stretch`; source validation, rounded image rendering, ownership, and lifecycle boundaries are documented and partially covered by tests/fixtures. | The UI host does not load assets from paths, URLs, imports, or browser asset modules. The game owns texture loading and lifetime; theme registration borrows the region and texture. |
| Hot reload | Partial | `ScriptUiReloader` polls a caller-selected local bundle on the UI thread, enforces a 4 MiB strict-UTF-8 limit, compares content hashes, and reports changed/error/closed results. Syntax errors keep the active UI; execution errors after swap begins close the runtime. | This is a development polling helper, not HMR: no source watcher, bundler server, module graph, component state preservation, or production asset reload is supplied. Rebuild TSX separately and poll its generated bundle. |
| Inspector | Partial | `SceneInspection` creates immutable read-only snapshots of live `GameObject` rows, `Transform2D`/`Transform3D` values, 3D parent hierarchy, and component summaries. `RuntimeInspector` presents that scene view in a desktop Stage overlay, toggled with F1, and clears selection on scene replacement or disposal. [`SceneInspectionTest`](../javity-ui/src/test/java/org/javity/ui/inspector/SceneInspectionTest.java) covers immutability, read-only behavior, hierarchy, scene ID reuse, object removal, and disposal. | This inspects the game scene, not the OneJS/native UI tree. It does not expose `UiDocument`/React nodes, UI props/classes, Yoga bounds, or React DevTools. An inspector for UI tree and layout remains separate follow-up work. |
| Platforms | Partial | The current host is concrete on desktop: `javity-ui` selects LWJGL and Yoga native classifiers for the host OS, while `javity-script` uses GraalJS Community. | The audited module dependencies and entry points provide no Android binding or web host. Do not claim Android/web support, cross-platform native Yoga availability, or OneJS Unity runtime parity from desktop behavior. |

The eleven areas above are deliberately not averaged: they have different scope and importance, so a single percentage would imply a meaningful denominator that does not exist.

## Evidence inspected

- [AGENTS.md](../AGENTS.md) defines `javity-script` as an optional GraalJS/React host, limits the native markup to explicit utility classes, and says Android/web require separate bindings and tests.
- [onejs-port.md](onejs-port.md) documents the runtime lifecycle, single React host, primitive bridge, scheduler limits, development reloader, and failure behavior.
- [declarative-ui.md](declarative-ui.md) defines the control/property schema, markup subset, utility classes, registered image contract, and clipping limits.
- [plugin-feature-coverage.md](plugin-feature-coverage.md) reports the desktop comparison and smoke evidence; those claims were checked against the narrower source/test contracts rather than treated as a compatibility specification.
- [`UiDocument`](../javity-ui/src/main/java/org/javity/ui/declarative/UiDocument.java) validates the finite control and property sets, reconciles keyed Scene2D actors, and attaches the documented native input listeners.
- [`UiMarkup`](../javity-ui/src/main/java/org/javity/ui/declarative/UiMarkup.java) parses XML-compatible markup, rejects unsupported tags/attributes, and limits nesting and node count.
- [`UtilityStyles`](../javity-ui/src/main/java/org/javity/ui/flex/UtilityStyles.java) implements the explicit style vocabulary and rejects unknown utilities.
- [`ScriptUiRuntime`](../javity-script/src/main/java/org/javity/script/ScriptUiRuntime.java) creates a GraalJS context with host access, class lookup, IO, and native access disabled, installs the scheduler and primitive bridge, and caps host callbacks.
- [`ScriptUiReloader`](../javity-script/src/main/java/org/javity/script/ScriptUiReloader.java) implements bounded local-file polling and content-based reload detection.
- [`SceneInspection`](../javity-ui/src/main/java/org/javity/ui/inspector/SceneInspection.java) and [`RuntimeInspector`](../javity-ui/src/main/java/org/javity/ui/inspector/RuntimeInspector.java) implement a scene/GameObject inspector overlay, now with typed transform editing and undo/redo (see runtime-tools.md). It is not an inspector for the React or `UiDocument` tree.
- [`web/javity-ui/README.md`](../web/javity-ui/README.md) and [`package.json`](../web/javity-ui/package.json) define separate build/test scripts and the deliberately restricted React host contract.
- Tests inspected include [`UiDocumentTest`](../javity-ui/src/test/java/org/javity/ui/declarative/UiDocumentTest.java), [`UiMarkupTest`](../javity-ui/src/test/java/org/javity/ui/declarative/UiMarkupTest.java), [`ScriptUiRuntimeTest`](../javity-script/src/test/java/org/javity/script/ScriptUiRuntimeTest.java), [`ScriptUiReloaderTest`](../javity-script/src/test/java/org/javity/script/ScriptUiReloaderTest.java), and [`host-tree.test.cjs`](../web/javity-ui/test/host-tree.test.cjs). This audit inspected test code; it did not run Gradle or npm tests.

## Recommended TODOs

These are ordered as follow-up work, not as claims that the features already exist:

1. **UI tree inspector:** extend the existing scene/GameObject overlay separately with a read-only snapshot of `UiDocument`/React nodes, keys/types/classes/props, and Yoga-computed bounds; show runtime/reload errors and recent UI action events. Add tests for snapshot updates after React reconciliation and document close. The current `SceneInspection`/`RuntimeInspector` only inspect game objects, transforms, and component summaries. Keep editing and arbitrary script evaluation out of the first scope.
2. **Lock down the compatibility contract:** add a concise supported/unsupported API table to user-facing authoring docs and keep package props, native validation, and tests in sync when controls or event types are added. Treat DOM, CSS, and Tailwind expansion as separate explicit decisions.
3. **Make the development reload loop easier to operate:** add a documented desktop example that builds `dev.tsx`, polls the bundle, and surfaces `lastError`; retain current parse-error preservation and execution-error behavior. Decide separately whether state-preserving HMR is worth implementing.
4. **Expand input only for a concrete game need:** specify pointer/touch/wheel and propagation contracts before exposing new events; add native Stage tests and a React-facing test for each accepted event.
5. **Add a platform port only as a separate project:** Android needs compatible Yoga/graphics bindings and device validation; web needs a browser/wasm renderer or an explicitly different host. Reuse the declarative contract where useful, but do not label desktop tests as platform coverage.

The current implementation is useful as a native game HUD and settings UI host. Keep “OneJS-inspired native React UI” as the scope statement until specific additional contracts are implemented and verified.
