# Porównanie GameObject i komponentów z java-lab

Audyt z 2026-10-15 względem commitu `Radomiej/java-lab` [`f6f3f168bf688059f1f52cecf01aa53ec4b3cdc2`](https://github.com/Radomiej/java-lab/commit/f6f3f168bf688059f1f52cecf01aa53ec4b3cdc2), na podstawie [`shared/lab-game-v2/API.md`](https://github.com/Radomiej/java-lab/blob/f6f3f168bf688059f1f52cecf01aa53ec4b3cdc2/shared/lab-game-v2/API.md) i [`src/data/gameCoreRuntime.js`](https://github.com/Radomiej/java-lab/blob/f6f3f168bf688059f1f52cecf01aa53ec4b3cdc2/src/data/gameCoreRuntime.js). ## Wskazówki dla kodu gry

`getComponent(Type)` zwraca `null`, gdy komponentu brakuje. Pobierz go raz i sprawdź wynik, zamiast robić `hasComponent` i zaraz potem `getComponent`. `requireComponent(Type)` może służyć do opcjonalnego sprawdzania konfiguracji przy inicjalizacji; nie używaj wyjątków do zwykłego sterowania rozgrywką.

## Możliwe dalsze kroki zgodności

1. Dodać do `Component` metody `getComponents(Class)`, `requireComponent(Class)` i `removeComponents(Class)`, delegujące do właściciela. To małe uzupełnienie API już dostępnego na `GameObject`.
2. Ujednolicić albo jasno opisać obsługę przestrzeni WORLD/SCREEN dla sprite'ów, kształtów i tekstu. Przed deklaracją zgodności trzeba sprawdzić kolejność kamery i UI.
3. Jeśli mapa MapLibre ma być zarządzana przez scenę, dodać cienki adapter cyklu życia `MapLibreMap` w opcjonalnym module MapLibre. Obecna mapa natywna i istniejące komponenty rastrowe mają różne role.

To są propozycje dalszej pracy nad zgodnością, nie część obecnego audytu. Do wyświetlenia prawdziwych danych Gorzowa można użyć obecnego wrappera natywnego MapLibre; brak adaptera komponentu nie oznacza braku natywnego renderera.
