# C1 UI parity evidence

The native declarative UI now uses a deliberately bounded Tailwind 4.3.3 utility vocabulary in `UtilityStyles` and a real Chromium-rendered HTML fixture in this directory. The browser runner uses the repository's Open Sans Regular TTF, waits for `document.fonts.ready`, captures at 1100×720 / DPR 1, and stores its metrics and PNGs here. Desktop `processResources` packages only the shared JSON fixture and generated reference metrics, so application launch does not need Node or Chromium.

The fixture covers three nested flex levels, row/column layout, inherited text color and font sizing, 14/16/18/20/24px text with measured line boxes, buttons, input, progress, card, and a clipped scroll pane. The supported styles are the strict catalog in `UtilityStyles`; unsupported media/layout variants throw. The browser's Chromium build hides its native overlay scrollbar even when the CSS scrollbar pseudo-elements are styled, so the reference uses a small custom HTML thumb/track driven by the actual scroll node's `scrollTop`, `clientHeight`, and `scrollHeight`. The runner proves that the thumb moves after scrolling.

Run the reference from the repository root with `npm --prefix web/javity-ui-reference ci`, `npm --prefix web/javity-ui-reference run css`, and `npm --prefix web/javity-ui-reference run compare`. Run native verification with JDK 25 and `./gradlew :javity-ui:test :javity-desktop:uiParitySmoke`; a server requires Xvfb and Mesa.

The real-browser/native comparison checks all keyed fixture actor boxes, five stable interior color samples, the base input border pixel, button and input hover, input focus, button and input disabled state, and the disabled declarative button callback. State colors allow at most 3 channel values of raster/compositing error; stable interior colors allow 2. The disabled-button input probe sends actual Stage touch down/up and confirms the `UiDocument` callback remains uncalled. Every state capture clears the framebuffer first.

Latest native evidence is in `artifacts/ui-parity-native.png`, `artifacts/ui-parity-native-metrics.json`, `artifacts/ui-parity-comparison.json`, and `artifacts/ui-parity-state-comparison.json`. Latest Chromium evidence is `tailwind-4.3.3-reference.png`, the hover/focus/disabled/scroll captures, and `reference-metrics.json`. The native smoke passes with maximum actor-box error 2.12px at `header-left.width`, interior color-channel error 0, and input base-border error 0. At the scroll thumb's exact slate-400 pixels, Chromium measures a 6×21px colored box at (428,591), while native measures 6×22px at (429,591): the native thumb starts 1px to the right and is 1px taller. The comparison permits at most 2px per thumb bound.

Glyph ink bounds were measured from the screenshots, not inferred from label actor boxes. Native minus browser `(x,y,width,height)` residuals are: header label `(0,0,+2,0)`, inherited 16px ` (0,0,-1,0)`, 20px `(0,0,-1,0)`, 24px `(0,0,+3,0)`, card title `(-1,-1,+4,0)`, and card body `(0,0,-1,0)`. These small width/vertical-origin differences remain from font rasterization and glyph advance metrics across Chromium and FreeType; line-box and geometry checks remain separate. The same 16px font/color inheritance is projected through the declarative tree; background, padding, and border are never inherited.

This is a measured subset for the listed fixture, not a promise to implement the full CSS or Tailwind language. `UtilityStyles` defaults unclassified text to black and unclassified controls to no fill to match the HTML reset; utility classes supply visual styles explicitly. The native smoke also constructs a 32px TrueType theme and verifies its `text-base` and `text-2xl` labels use 16px/24px fonts and 24px/32px line boxes. It checks that text sizing on a borrowed BitmapFont leaves the font's shared metrics unchanged. Per-node sized cached fonts are owned by `UiTheme`; supported visual state variants are limited to Button and TextField styles and unsupported node/state pairs fail validation before tree mutation. State variants reject layout changes such as numeric border widths.


Root final review added an automatic glyph-ink regression gate: vertical origin/height error at most 1px, width error at most 4px, based on the measured eight samples. Scrollbar styles keep the 6px thickness and 8px minimum knob length through class updates, with independent vertical/horizontal styles. Automatic paragraph wrapping is not implemented; this fixture proves single-line typography, not browser paragraph flow.
